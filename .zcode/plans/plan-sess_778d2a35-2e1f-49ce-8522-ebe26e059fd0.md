# Port Bwend backend from Vapor (Swift) to Convex (TypeScript)

Move the entire iOS app backend to the existing Convex deployment (helpful-owl-232). After this, the Vapor backend (`bwend-backend/`) is retired — everything runs on Convex + Vercel. The iOS app needs **zero changes** — same API contract, same JWT auth pattern.

## Architecture

```
bwend-ios  ──HTTPS──▶  Convex (helpful-owl-232)
  │                        │
  │ Bearer JWT              ├─ Spotify API (token exchange, /me/top/*, /recommendations)
  │ (HS256, issued          ├─ VibeScoreEngine (pure TS)
  │  at connect time)       ├─ CompatibilityReader (pure TS)
  │                         ├─ InviteCodeGenerator (pure TS)
  │                         └─ JWT sign/verify (WebCrypto HMAC-SHA256)
  │
  └──bwend://spotify-callback──▶  Spotify (PKCE, no server round-trip for auth)
```

All endpoints become Convex **httpActions** (so the iOS app calls them as plain HTTPS URLs, same as before). The iOS `APIClient.baseURL` changes from the Vapor server URL to the Convex site URL (`https://helpful-owl-232.eu-west-1.convex.site/api`).

## Files to create (all under `convex/`)

### Pure logic modules (ported verbatim from Swift)

1. **`convex/lib/vibeScore.ts`** — the scoring engine. Exact same weights (0.25/0.25/0.15/0.15/0.10/0.10), Jaccard, similarity functions, tempoRange=140, eraRange=30, aggregateAudioProfile. Pure functions, zero I/O. **Must produce byte-identical scores to the Swift version.**

2. **`convex/lib/compatibilityReader.ts`** — the qualitative copy generator. Same thresholds (strong=0.75, weak=0.40), same copy fragments, same "replace 2nd fragment with artist anchor" logic.

3. **`convex/lib/inviteCode.ts`** — invite code generator. Same alphabet (`abcdefghijkmnpqrstuvwxyz23456789`, 32 chars, no ambiguous chars), 8-char codes, collision retry.

4. **`convex/lib/jwt.ts`** — HS256 JWT sign/verify using WebCrypto (`crypto.subtle.importKey` + HMAC-SHA256). Same claims as Swift: `{sub: spotifyId, name, iss: "bwend", iat, exp}`. 24h lifetime. Signed with `BWEND_SESSION_SECRET`.

5. **`convex/lib/spotify.ts`** — Spotify API client. Port of `SpotifyService.swift`: exchangeAuthCode, me, topTracks (with fractional releaseYear parsing), topArtists, audioFeatures (batched 100), recommendations (3-decimal float formatting, rounded tempo). Uses `fetch` with the same headers/error mapping.

### Schema

6. **`convex/schema.ts`** — extend the existing schema (keep `waitlist` table). Add 3 tables:
   - `bwendProfiles`: spotifyUserId (unique), displayName, topTracks[], topArtists[], audioProfile{}, spotifyTokenBlob
   - `invites`: code (unique), inviterSpotifyUserId, inviteeSpotifyUserId?, status (union literal), createdAt, claimedAt?, expiresAt
   - `matches`: inviteId (v.id("invites")), userASpotifyUserId, userBSpotifyUserId, vibeScore, breakdown{}, anchorTrack?, sharedTopArtistNames[], sharedTopTrackNames[], compatibilityRead, createdAt
   - Indexes: unique on spotifyUserId, unique on code, indexes on both match user IDs for the list query

### HTTP API (the iOS-facing endpoints)

7. **`convex/http.ts`** — the HTTP router. Registers all endpoints under `/api/`:
   - `POST /api/auth/spotify` → `spotifyConnect` action (public — exchanges code, issues JWT)
   - `POST /api/invites` → `createInvite` mutation (authed)
   - `GET  /api/invites/:code` → `fetchInvite` query (authed)
   - `POST /api/invites/:code/claim` → `claimInvite` action (authed, calls Spotify for anchor)
   - `GET  /api/matches` → `listMatches` query (authed)
   - `GET  /api/matches/:id` → `fetchMatch` query (authed)
   - `GET  /api/health` → returns "ok"

8. **`convex/auth.ts`** — an `httpAction` middleware helper that reads the Bearer JWT, verifies it via `lib/jwt.ts`, and returns the `{spotifyUserId, name}` identity. Every authed endpoint wraps its handler with this. Invalid/expired → 401 JSON.

9. **`convex/spotifyConnect.ts`** — the auth entry point action. Mirrors `SpotifyController.connect`: exchange code → fetch me/tracks/artists/features → aggregate audio profile → upsert profile → issue JWT → return `{token, spotifyId, displayName, topTrackCount, topArtistCount}`.

10. **`convex/invites.ts`** — create/fetch/claim. The claim action does everything the Swift controller did: validate → score → compute shared names → pick anchor track (Spotify recommendations, best-effort) → generate compatibility read → insert match → update invite.

11. **`convex/matches.ts`** — fetch (full reveal data) + list (history summaries). Same response shapes as Swift.

## iOS changes (minimal)

Only one file changes: `APIClient.swift` — update `baseURL` to point at the Convex site URL instead of the Vapor server. The path structure changes from `/auth/spotify` to `/api/auth/spotify` (added `/api` prefix). Everything else stays the same.
